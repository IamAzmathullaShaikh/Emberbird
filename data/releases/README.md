# Ember Registry Handbook

This directory is the **single source of truth** for release metadata:

| File | Role |
|---|---|
| `releases.schema.json` | The metadata contract (Draft-07 subset). A schema file, not configuration. |
| `releases.json` | The registry itself — **generated by `scripts/build_registry.py`, never hand-edited**. |
| `GOVERNANCE.md` | Schema evolution, ownership, deprecation, and emergency-recovery rules. |

To change registry *data*, change reality (publish a release) or the generator,
then regenerate. To change registry *shape*, follow the schema evolution rules
in [GOVERNANCE.md](GOVERNANCE.md) — every change requires a `schema_version`
bump, a migration plan, consumer review, and a `compatibility_level` decision.

## Release Engine CLI

All registry operations go through the Release Engine
(`platform/release-engine/release_engine/__main__.py`):

```bash
# Integrity + schema validation (CI Truth Gate — build.yml runs this)
python platform/release-engine/release_engine/__main__.py validate --schema

# Latest / per-release queries (offline, registry-only)
python platform/release-engine/release_engine/__main__.py latest
python platform/release-engine/release_engine/__main__.py release <release_id>

# Drift detection — compare a previous snapshot against the committed registry.
# Exit 0 = no drift, exit 2 = drift found (additions, removals, hash or asset
# changes; generation timestamps and provenance are excluded by design).
python platform/release-engine/release_engine/__main__.py diff <previous.json> --fail-on-drift

# Vault mirror verification — checks each vault entry's mirror_status against
# the published GitHub asset (network). --write persists the updated statuses.
python platform/release-engine/release_engine/__main__.py verify --write

# Policy write path for `recommended` (Execution Contract clause 9). Refuses
# to run without recommended_by provenance, decided_at, and a rationale.
# <decision.json> shape:
#   {"release_id": "...", "recommended_by": "...", "decided_at": "YYYY-MM-DD", "rationale": "..."}
python platform/release-engine/release_engine/__main__.py apply-policy --decision <decision.json>
```

The registry validates with **no network access** (Repository Independence
Rule, charter). Only `verify` and the generator touch the network.

## Regeneration

```bash
python scripts/build_registry.py            # regenerate from published GitHub reality
```

Regeneration is idempotent against unchanged reality: policy decisions
(`recommended`, root `policy`) and vault mirror statuses are carried over from
the previous registry. The daily scheduled workflow
(`registry-drift.yml`) regenerates and diffs — it never auto-commits;
published reality enters the repository through reviewed changes only.
